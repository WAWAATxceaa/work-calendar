# ระบบปฏิทินการปฏิบัติงาน (Node.js + Real-time SSE)

เว็บแอปพลิเคชันระบบปฏิทินและกำหนดการปฏิบัติงานสำหรับองค์กร/สถาบัน บันทึกข้อมูลถาวรเป็นไฟล์ JSON บนเซิร์ฟเวอร์ และรองรับการทำงานแบบ **Real-time ซิงก์ร่วมกันได้ทุกเครื่องในเครือข่ายทันที** ผ่าน **Server-Sent Events (SSE)** ภาษาไทยทั้งระบบ แสดงผลปีเป็น **พ.ศ.** รองรับมือถือ (Mobile-First) และโหมดมืด (Dark Mode)

---

## 🏗️ สถาปัตยกรรมระบบ (System Architecture)

```
┌────────────────────────────────────────────────────────────────────────┐
│                        ผู้ใช้งาน / Client Devices                     │
│   (เครื่องคอมฯ 1: Chrome)    (เครื่องคอมฯ 2: Edge)        (มือถือ/แท็บเล็ต) │
└────────────▲────────────────────────▲────────────────────────▲─────────┘
             │                        │                        │
             │   HTTP REST API        │  Server-Sent Events    │
             ▼   (GET, POST, DELETE)  ▼  (/api/stream)         ▼
┌────────────────────────────────────────────────────────────────────────┐
│               เซิร์ฟเวอร์หลัก: Node.js + Express (server.js)           │
│  - Port: 3000 (bind 0.0.0.0 เพื่อให้ทุกเครื่องในวง LAN เข้าใช้งานได้)    │
│  - Static File Server: เสิร์ฟหน้าเว็บจากโฟลเดอร์ public/                │
│  - SSE Hub: Broadcast ข้อมูลล่าสุดไปยังทุก Client ทันทีที่มีการเปลี่ยนแปลง │
│  - File Manager: จัดการบันทึกข้อมูลแบบปลอดภัย (Safe Atomic Write)       │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│              ฐานข้อมูลไฟล์ (File-Based Storage) & สำรองข้อมูล            │
│  - data/events.json: ไฟล์ข้อมูลหลัก (Events, Users, Holidays)           │
│    (เขียนลง temp file ก่อนแล้ว rename ป้องกันข้อมูลเสียหาย)               │
│  - data/backup/events-YYYYMMDD.json: สำรองข้อมูลอัตโนมัติวันละ 1 ครั้ง     │
└────────────────────────────────────────────────────────────────────────┘
```

### จุดเด่นของระบบ:
1. **บันทึกข้อมูลถาวรในเครื่อง/เซิร์ฟเวอร์:** จัดเก็บในไฟล์ `data/events.json` ทันที ไม่ต้องติดตั้งฐานข้อมูลภายนอก (สร้างไฟล์และข้อมูลตัวอย่างเริ่มต้นให้อัตโนมัติเมื่อรันครั้งแรก)
2. **ปลอดภัยสูงสุดด้วย Atomic Write:** เขียนลงไฟล์ชั่วคราว `.tmp` ก่อน แล้วจึงเปลี่ยนชื่อไฟล์ (`fs.renameSync`) ป้องกันปัญหาไฟล์เสียหายแม้ไฟดับขณะบันทึก
3. **สำรองข้อมูลอัตโนมัติทุกวัน:** มีระบบสำรองข้อมูลรายวันในโฟลเดอร์ `data/backup/events-YYYYMMDD.json`
4. **เรียลไทม์ข้ามเครื่องแท้จริง (Server-Sent Events):** ทุกเครื่องที่เปิดหน้าเว็บจะต่อ stream `/api/stream` เมื่อเครื่องใดเครื่องหนึ่งเพิ่ม/แก้ไข/ลบงาน ทุกเครื่องจะได้รับข้อมูลล่าสุดทันทีโดยไม่ต้องกดรีเฟรช
5. **บอกสถานะการเชื่อมต่อชัดเจน:**
   - 🟢 **เชื่อมต่อเซิร์ฟเวอร์แล้ว** เมื่อเชื่อมต่อ stream สำเร็จ
   - ⚠️ **ออฟไลน์** เมื่อขาดการเชื่อมต่อจากเซิร์ฟเวอร์
6. **ส่งออก / นำเข้า CSV (ใช้กับ Google Sheets / Excel ได้ทันที):**
   - ปุ่ม **"ส่งออก CSV"** ดาวน์โหลดไฟล์พร้อม UTF-8 BOM รองรับภาษาไทยสมบูรณ์
   - ปุ่ม **"นำเข้า CSV"** อัปโหลดไฟล์เพื่อ Upsert งานเข้าสู่ฐานข้อมูล และส่งอัปเดตไปทุกเครื่องทันที

## 🚀 ขั้นตอนการติดตั้งและเริ่มใช้งาน

### ข้อกำหนดเบื้องต้น
- ติดตั้ง **[Node.js](https://nodejs.org/)** (เวอร์ชัน 18 ขึ้นไป) บนเครื่องเซิร์ฟเวอร์/เครื่องหลัก

### 1. ติดตั้ง Dependencies
เปิด Terminal หรือ PowerShell ในโฟลเดอร์โปรเจกต์ แล้วพิมพ์คำสั่ง:

```bash
npm install
```

### 2. เริ่มต้นเซิร์ฟเวอร์
พิมพ์คำสั่ง:

```bash
npm start
```

เมื่อเซิร์ฟเวอร์เริ่มทำงาน จะแสดงข้อความในคอนโซล:

```text

  ║   📅 ระบบปฏิทินการปฏิบัติงาน                    ║
  ║   Node.js Server — Real-time SSE              ║
  ╠═══════════════════════════════════════════════╣
  ║   🟢  http://localhost:3000                    ║
  ║   📂  ข้อมูลจัดเก็บที่ data/events.json          ║
  ║   💾  สำรองอัตโนมัติที่ data/backup/              ║
  ╚═══════════════════════════════════════════════╝

  💡 เปิดจากเครื่องอื่นในเครือข่ายเดียวกัน:
     http://<IP ของเครื่องนี้>:3000
```

## 🌐 การเข้าใช้งานระบบ

### เข้าใช้งานจากเครื่องเดียวกัน:
เปิดเบราว์เซอร์ไปที่:
👉 **`http://localhost:3000`**

### เข้าใช้งานจากเครื่องอื่นหรือมือถือในเครือข่าย Wi-Fi/LAN เดียวกัน:
1. หา IP เครื่องหลัก (เซิร์ฟเวอร์):
   - บน **Windows**: เปิด Command Prompt หรือ PowerShell แล้วพิมพ์ `ipconfig` ดูที่ **IPv4 Address** (เช่น `192.168.1.150`)
   - บน **macOS / Linux**: พิมพ์ `ifconfig` หรือ `ip a`
2. บนอุปกรณ์อื่น (คอมพิวเตอร์เครื่องอื่น, โทรศัพท์มือถือ, แท็บเล็ต) ที่ต่อ Wi-Fi หรือวง LAN เดียวกัน เปิดเบราว์เซอร์ไปที่:
   👉 **`http://192.168.1.150:3000`** *(แทนที่ด้วย IP จริงของเครื่องเซิร์ฟเวอร์)*

## 🧪 การทดสอบ Real-time ข้ามเครื่อง/ข้ามเบราว์เซอร์

1. **เปิดหน้าจอพร้อมกัน 2 หน้าต่าง:**
   - หน้าต่างที่ 1: Google Chrome เปิด `http://localhost:3000`
   - หน้าต่างที่ 2: Microsoft Edge หรือมือถือ เปิด `http://localhost:3000` หรือ `http://<IP>:3000`
2. เข้าสู่ระบบทั้งสองหน้าต่าง (สามารถเลือกผู้ใช้คนเดียวกันหรือต่างคนก็ได้)
3. สังเกตแถบสถานะด้านบนขวาจะแสดง **"🟢 เชื่อมต่อเซิร์ฟเวอร์แล้ว"**
4. ในหน้าต่างที่ 1 กดปุ่ม **"➕ เพิ่มงาน"** แล้วกรอกข้อมูลงานใหม่ จากนั้นกด **"บันทึก"**
5. **สังเกตที่หน้าต่างที่ 2:** งานใหม่จะปรากฏขึ้นบนปฏิทินทันทีโดยไม่ต้องกดรีเฟรชหน้าจอ!
6. ลองคลิกเปลี่ยนสถานะงาน (เช่น จาก "รอดำเนินการ" เป็น "เสร็จแล้ว") ที่เครื่องหนึ่ง อีกเครื่องจะอัปเดตสีและสถานะทันทีแบบ Real-time

## 📡 รายการ REST API & SSE Endpoints

| Method | Endpoint | รายละเอียด |
|---|---|---|
| `GET` | `/api/stream` | **Server-Sent Events (SSE):** รับข้อมูลอัปเดตแบบเรียลไทม์ทุกครั้งที่มีการแก้ไข |
| `GET` | `/api/events` | ดึงข้อมูลงาน, ผู้ใช้, และวันหยุดทั้งหมด |
| `POST` | `/api/events` | เพิ่มงานใหม่ หรือแก้ไขงานเดิมตาม `id` (พร้อมบันทึก `updatedAt` อัตโนมัติ) |
| `DELETE` | `/api/events/:id` | ลบงานตาม `id` |
| `GET` | `/api/users` | ดึงรายชื่อผู้ใช้ทั้งหมด |
| `POST` | `/api/users` | เพิ่มหรือแก้ไขผู้ใช้ตามอีเมล |
| `DELETE` | `/api/users/:email` | ลบผู้ใช้ |
| `GET` | `/api/holidays` | ดึงรายการวันหยุดทั้งหมด |
| `POST` | `/api/holidays` | เพิ่มหรือแก้ไขวันหยุดตามวันที่ |
| `DELETE` | `/api/holidays/:date` | ลบวันหยุด |
| `GET` | `/api/export-csv` | ส่งออกข้อมูลงานทั้งหมดเป็นไฟล์ CSV (UTF-8 with BOM สำหรับ Excel) |
| `POST` | `/api/import-csv` | นำเข้าข้อมูลงานจากเนื้อหา CSV และ Broadcast ไปยังทุกเครื่อง |

## 📊 การส่งออกและนำเข้าข้อมูลกับ Google Sheets

### ส่งออกเป็น CSV ไปใช้ใน Google Sheets:
1. คลิกเมนู **"แดชบอร์ดสรุป"** หรือเมนูด้านซ้าย **"ส่งออก CSV"**
2. ไฟล์จะถูกดาวน์โหลดในชื่อ `events-YYYY-MM-DD.csv`
3. เปิด Google Sheets → เลือก **ไฟล์ (File) → นำเข้า (Import) → อัปโหลด (Upload)** เลือกไฟล์ CSV ที่เพิ่งดาวน์โหลด

### นำเข้าข้อมูลจาก Google Sheets เข้าสู่ระบบ:
1. ใน Google Sheets ให้ไปที่ **ไฟล์ (File) → ดาวน์โหลด (Download) → ค่าที่คั่นด้วยเครื่องหมายจุลภาค (.csv)**
2. ในเว็บแอปพลิเคชัน (ล็อกอินเป็น Admin) คลิกปุ่ม **"📥 นำเข้า CSV"**
3. เลือกไฟล์ CSV ที่ดาวน์โหลดมา ระบบจะทำการ Upsert งานทั้งหมดลงในไฟล์ `data/events.json` และทุกเครื่องจะเห็นข้อมูลใหม่ทันที

## ⚡ การเชื่อมต่อตรงผ่าน Google Apps Script Web App (API Sync)

หากต้องการดึงข้อมูลหรือซิงก์ข้อมูลตรงกับ Google Sheets ผ่าน Web App API:

1. **ตั้งค่าใน Google Spreadsheet:**
   - ไปที่ **ส่วนขยาย (Extensions) → Apps Script**
   - นำโค้ดจาก `Code.gs` ไปวางแล้วบันทึก
   - คลิก **Deploy → New deployment**
   - ประเภท: **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone** *(สำคัญมาก ต้องเลือก Anyone เพื่อให้เบราว์เซอร์เรียก API ได้)*
   - คัดลอก Web App URL ที่ลงท้ายด้วย `/exec`

2. **ใส่ URL ในไฟล์ `config.js`:**
   เปิดไฟล์ `config.js` (และ `public/config.js`) แล้ววาง URL:
   ```javascript
   export const APPS_SCRIPT_URL = "https://script.google.com/macros/s/AKfycby.../exec";
   ```

3. **มาตรฐานการเรียก API ที่ปลอดภัยจากปัญหา CORS / Failed to fetch:**
   - **GET Request (เช่น `getEvents`, `ping`):** เรียกผ่าน `fetch(APPS_SCRIPT_URL + '?action=getEvents')` โดยไม่ใส่ Headers และไม่ใช้ credentials เพื่อป้องกัน CORS Preflight
   - **POST Request (เช่น `batchUpsertEvents`):** เรียกผ่าน `fetch(APPS_SCRIPT_URL, { method: 'POST', headers: {'Content-Type': 'text/plain;charset=utf-8'}, body: JSON.stringify({...}), redirect: 'follow' })`
   - เมื่อเปิดแอป ระบบจะยิง `?action=ping` ทดสอบให้อัตโนมัติ หากมีปัญหาจะแจ้งเตือนให้ตรวจสอบสิทธิ์และ URL ทันที
